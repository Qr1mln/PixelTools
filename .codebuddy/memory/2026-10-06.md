## bind 后端改造 (用户拍板方案: 加 windows-capture 可切换后端 / 只做窗口激活+状态查询 / bind 签名不变)
- **选型依据 (先调研后决策)**：pywin32(已装, 够用) | **windows-capture 2.0.1 (2026-08, Rust, MIT, 唯一值得新增)** | DXcam(整屏非窗口) | pywinauto 0.6.9 / uiautomation 2.0.29(控件自动化, 游戏窗口无 UIA, 图色用不上) | PyGetWindow 0.0.9(2020 停更, 纯 pywin32 薄封装, **不引入**)。`uv add windows-capture` 已装。
- **windows-capture 实测结论 (别再猜)**：
  - 构造 `WindowsCapture(cursor_capture, draw_border, secondary_window, minimum_update_interval, dirty_region, monitor_index, window_name, window_hwnd)` —— **有 `window_hwnd`, 按句柄精确捕获, 不要用 window_name**。
  - **不能用 `@cap.event` 装饰器**(它按 `handler.__name__` 只认 `on_frame_arrived`/`on_closed`, 其它名字抛 ValueError)；直接 `cap.frame_handler = fn` / `cap.closed_handler = fn`。
  - `start_free_threaded()` 返回 `CaptureControl`(有 `.stop()`/`.wait()`/`.is_finished()`)；`WindowsCapture` 本身**没有** stop。
  - `Frame.frame_buffer` 是 **BGRA 且零拷贝视图**, 只在回调期间有效 → 必须 `np.array(..., copy=True)` 或 `.copy()`。`Frame.crop(sw, sh, ew, eh)` = numpy 切片 `[sh:eh, sw:ew]`, **末端不含(半开)**。WGC 仅在窗口内容变化时推帧, 静止窗口不产生拷贝。
- **DPI 坐标系 (关键坑, 与旧的双重缩放坑叠加)**：WGC 帧是**物理像素**, 且帧尺寸 = **DWM 可视边框**尺寸, **≠ GetWindowRect**。实测 Win11/150%: GetWindowRect=1248x884, DWM 扩展边框(DWMWA_EXTENDED_FRAME_BOUNDS=9)=WGC 帧=1234x877(差的是 Win11 不可见缩放边框)。按 GetWindowRect 推算帧内客户区原点误差 **15.5/255**, 按 DWM 推算误差 **0.098/255**。整帧逐像素比对: 抽样点完全一致, 平均误差 2.86/255, 3.2% 差异集中在 alpha=0 的透明圆角边框 + 闪烁光标(非映射问题)。
  - 故 `_window_origin` 必须取 `dwm_frame_origin()`(ctypes dwmapi), 取不到才退回 GetWindowRect 左上角。
  - 换算链: `帧内 = 客户区物理原点 + 逻辑*scale - 窗口可视边框原点`; 闭区间 x2 要 +1 再取整得半开末端。
